# Why GPT? — Project Bridge

Read this file first when a fresh ChatGPT conversation enters this repository.

## Purpose

Why GPT? studies why large language models appear unusually capable when independently intelligible distinctions must become jointly determining before a coherent output can be produced.

This project is associative and downstream. It should preserve live paths back to the repositories from which its distinctions came.

## First act

At the start of a relevant conversation:

1. Read `PROJECT.md`.
2. Read `project.json` for the current shared state.
3. Follow the source repositories relevant to the question.
4. Reconstruct the needed distinction from its native source before extending it.
5. When a genuinely new stable proposition emerges, update `project.json` so later conversations can inherit it.

Do not treat this file as a substitute for the sources.

## Current framework

The project presently holds together four pieces:

- **Inheritance:** distinctions become available and can remain consequential.
- **Context / prompt construction:** a prompt can make selected distinctions jointly operative.
- **Conjunction:** independently distinguishable constraints can become mutually conditioning rather than remain independently realized meanings.
- **Generative resolution:** an LLM can resolve simultaneous contextual constraints into a coherent continuation that was not explicitly supplied.

Working sequence:

**distinctions become available → they persist → context makes them jointly operative → each constrains the others → the model generates under the combined field → an integrated intelligibility crystallizes**

## Jyotiṣa as a test field

Jyotiṣa is not introduced as something the reader must believe. It is an independently inherited interpretive system containing many separately nameable factors. Once a chart and its conventions are fixed, it supplies a constrained symbolic configuration.

The question is whether competent interpretation requires the same operation found in Persistence: preserving distinctions while refusing to let them retain isolated realized meanings.

Integration is not proof of empirical truth.

## Why GPT matters

The stronger hypothesis is:

> A large language model may be unusually suited to co-determined intelligibility because its output is generated under many simultaneous contextual constraints.

A strong prompt does not merely list requirements. It creates a field in which each supplied distinction changes what counts as a satisfactory realization of the others.

Prompt quality should therefore be judged by structural convergence rather than repeated wording.

## Deeper question

> **What must language be, for GPT to be possible?**

Human language carries traces of distinctions made, relations established, errors corrected, conclusions inherited, and wholes integrated. GPT is trained on those traces. The recoverability of structure from those traces is itself an object of study.

Another formulation is:

> **What passes?**

What survives expression strongly enough that another system can recover structure and continue from it?

## Boundaries

Keep these distinctions live:

- structure is not meaning;
- intelligibility is not truth;
- interpretation is not obedience;
- recognition is not belief;
- GPT fluency is not evidence of consciousness;
- Jyotiṣa does not validate Persistence merely by resembling it;
- Persistence does not establish the empirical truth of Jyotiṣa;
- analogy remains open and secondary;
- the present conjunction concerns the mode of integration, not a one-to-one mapping of contents.

## Associative-project rule

This repository should preserve provenance instead of absorbing its sources.

When a new proposition is added, record where it came from, whether it is source-supported or inferred, what could reopen it, and where the originating material can literally be found.

The project should never become self-originating in its own memory.

## Shared-state protocol

`project.json` is the minimal cross-conversation state file.

A ChatGPT project with authorized GitHub access should read it at the start of relevant conversations and update it when stable new project state emerges. Preserve prior entries unless explicitly correcting them, increment the revision, include source locations where possible, and mark uncertainty rather than smoothing it over.

The GitHub Page reads `project.json`. The static browser page cannot securely write to GitHub; writes must come from an authorized GitHub client or a human Git client.
